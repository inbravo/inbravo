## Open Problems → my current focus

- **Vendor lock-in has moved to the semantic layer**  
  Designing exit-readiness into vendor-managed semantic layers before migration commits, not after.
  Snowflake Cortex, Databricks Unity Catalog, and Google Agentic Data Cloud all carry the same
  lock-in surface as the platforms they replaced. New labels, familiar trap.

- **The universal semantic layer isn't coming**  
  Coordinating semantically-driven artifacts across a heterogeneous estate instead — the universal
  semantic layer has been eighteen months away for a decade. OSI compliance is the line every
  target architecture has to cross from 2026 onwards.

- **Semantic drift is a compliance event, not a data quality one**  
  Detecting drift in agent-interpreted business logic before it surfaces as a Principle 2 breach,
  not after the auditor asks why the number changed. Auditors don't accept
  *"the model seemed confident"*.

- **Conversational BI breaks on real estates, not demo data**  
  Most NL-to-insight demos work on a clean star schema with five tables. Enterprise estates have
  50,000 tables, three conflicting definitions of "revenue," and a semantic layer nobody has
  maintained since 2019. Genie, Cortex Analyst, and Fabric Copilot are only safe in front of an
  executive when the semantic model underneath is governed. Almost none are.

- **Most cloud migrations just relocate the problem**  
  Agent-ready target architectures where governed semantic models are the query surface, not raw
  tables. One migration enables AI. The other moves the problem to the cloud at three times the cost.

- **Nobody designed where the agent stops**  
  Where governance and identity belong in the agent stack — AgentHarness (LangGraph, CrewAI, AG2)
  runs agents; AgentOS (Cedar policy, MS AGT, Unity AI Gateway, AgentCore) governs them.
  Conflating the two is how compliance debt gets designed in from day one. Ignoring both is vendor
  lock-in with better branding.
